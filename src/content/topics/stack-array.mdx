Think of a **stack of plates** in the cafeteria. You put a clean plate on **top**, and you take a plate from the **top**. The plate at the bottom was put there first and comes out last. That rule is **LIFO**: Last In, First Out.

A stack is an **ADT**: it is defined by its operations, not by how it is stored.

| Operation | Meaning |
| --- | --- |
| `push(x)` | put x on top |
| `pop()` | remove and return the top item |
| `peek()` / `top()` | look at the top item without removing it |
| `isEmpty()` | is there nothing on the stack? |
| `isFull()` | no room left (array version only) |

### Building it on an array

Keep an array `st[MAX]` and one integer **`top`**, the index of the top item. An empty stack has `top = -1`.

- **push**: `st[++top] = x;` moves top up, then writes.
- **pop**: `return st[top--];` reads, then moves top down.

The old value stays in the array after a pop, but it no longer counts. Only `0..top` is the stack.

### Overflow and underflow

- **Overflow**: push when `top == MAX - 1`. The array has no room.
- **Underflow**: pop when `top == -1`. There is nothing to take.

Always check before you act. These two checks are the most common exam marks on this topic.

### Where stacks show up

Undo/redo, the browser back button, **checking balanced brackets**, evaluating postfix expressions, and the **call stack** that makes recursion work (Phase 1).
