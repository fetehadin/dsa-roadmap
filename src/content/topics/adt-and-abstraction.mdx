          int get() const { return value; }

Think of a **TV remote**. You know *what* the buttons do: power, volume up, next channel. You have no idea *how* the infrared signal is encoded, and you don't need to. If the manufacturer redesigns the circuit board, you keep pressing the same buttons.

**Abstraction** means showing only what matters to the user and hiding the rest.

### Abstract Data Type (ADT)

An **ADT** is the "remote control" view of a data type. It describes:

1. **the data** it holds (logically, e.g. "an ordered collection"),
2. **the operations** allowed on it (e.g. `push`, `pop`, `top`, `isEmpty`),
3. **the rules and error conditions** (e.g. "pop on an empty stack is an error").

It says nothing about arrays, pointers or memory.

### Data structure

A **data structure** is the *circuit board*: a concrete way to store the data so the ADT's operations work. The Stack ADT can be implemented with an array **or** a linked list. Both are valid data structures for the same ADT.

| | ADT | Data structure |
|---|---|---|
| Answers | *What* can I do? | *How* is it stored? |
| Level | Logical | Physical / implementation |
| Example | Stack, Queue, List | Array-based stack, linked list |

### In C++

A `class` makes this concrete: the **public** member functions are the ADT's interface, and the **private** members are the implementation. Hiding them is called **encapsulation**. Code that uses the class cannot break its internal rules.
