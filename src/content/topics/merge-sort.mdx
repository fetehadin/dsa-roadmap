Two people each hold a **sorted pile** of cards. To combine them, look at the top card of each pile, take the smaller one, and repeat. That **merge** is easy and takes one look per card.

Merge sort uses that trick recursively:

1. **Divide**: split the array into two halves.
2. **Conquer**: sort each half (recursively, until a piece has 1 item, which is already sorted).
3. **Combine**: merge the two sorted halves.

### The merge

```cpp
while (i <= mid && j <= hi)
    tmp.push_back(a[i] <= a[j] ? a[i++] : a[j++]);
// then copy whatever is left of either half
```

Using `<=` takes the **left** item when two are equal, so equal items keep their order: merge sort is **stable**.

### Why always n log n

Halving n repeatedly reaches 1 after **log₂ n** levels. Each level merges n items in total. So the cost is **n log n**, for sorted, reversed or random data alike. The price is the **O(n) temporary array**.

### Merge vs quick

| | Merge sort | Quick sort |
| --- | --- | --- |
| Worst case | O(n log n) | O(n²) |
| Extra space | O(n) | O(log n) |
| Stable | yes | no |
