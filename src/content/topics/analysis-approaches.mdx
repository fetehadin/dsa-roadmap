How do you decide which of two algorithms is "better"? There are two ways to find out.

### Empirical vs theoretical

- **Empirical analysis** = *run it and measure*. Implement both, time them on test data. It is easy to understand, but the result depends on the **computer, compiler, language, other running programs and the inputs you chose**. A fast laptop can make a bad algorithm look good.
- **Theoretical analysis** = *count the steps on paper* as a function of the input size **n**. It is independent of the machine and covers **all** inputs. This is what the rest of the chapter teaches.

### Qualitative vs quantitative

- **Qualitative**: Is it simple? Readable? Easy to maintain and modify? Does it handle errors?
- **Quantitative**: How much **time** (number of operations) and **space** (memory) does it use?

### Avoidable inefficiencies

These are "free" speed-ups that don't change the algorithm's idea:

1. **Redundant computation**: computing the same value again and again inside a loop. Move it out of the loop.
2. **Late loop termination**: continuing to loop after the answer is already known. `break` or `return` early.
3. **Repeated array referencing**: reading `a[i]` several times in one iteration. Read it once into a local variable.

### The time–space trade-off

You can often buy speed with memory: a lookup table, a set of seen values, a prefix-sum array. Or save memory by recomputing. Good design picks the balance the problem needs. On a phone with little memory you may choose differently than on a server.
