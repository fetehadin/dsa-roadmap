Looking for your keys in a row of 10 pockets: if they're in the **first** pocket you're done in one check; if they're in the **last** pocket (or not there at all) you check all 10. Same algorithm, same n, very different effort.

### The three cases

- **Best case**: the input arrangement that needs the **fewest** steps. Linear search: key at index 0 → **1 comparison**.
- **Worst case**: the arrangement that needs the **most** steps. Linear search: key last or missing → **n comparisons**.
- **Average case**: the expected steps over all inputs (assuming each is equally likely). Linear search, key present: on average $\frac{1 + 2 + \dots + n}{n} = \frac{n+1}{2}$ comparisons.

### Which one do we report?

Usually the **worst case**, because:

- it is a **guarantee**: the algorithm will never be slower;
- it often happens in practice (searching for something that isn't there);
- the average case needs assumptions about the input that may not hold.

> The case is about the **input arrangement** for a fixed n. "n = 1" is not the best case. A sorted array of size 1,000,000 can be the best case for insertion sort.
