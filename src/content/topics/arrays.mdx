Picture a **row of numbered lockers** in a corridor. Every locker is the same size and they sit right next to each other. If locker 0 is at the start of the corridor and each is 4 steps wide, you can walk straight to locker 7: it's 28 steps away. You never open lockers 0 to 6 on the way.

That is an **array**: same-type items stored **contiguously** (side by side) in memory.

### Why access is instant

The compiler knows three things: the **base address** (where `a[0]` lives), the **size of one item**, and the **index**. So

`address of a[i] = base + i × sizeof(type)`

One multiplication and one addition, for any `i`: **O(1) random access**.

### The price you pay

- **Fixed size**: `int a[100]` is static. Need 101? Make a new array and copy.
- **Insert / delete in the middle is O(n)**: every item after the gap must shift.
- **No bounds checking**: `a[100]` on a 100-item array compiles and runs, but reads or overwrites whatever is next in memory.

### 2-D arrays

A matrix `int m[R][C]` *looks* like a grid, but memory is one long line. C++ stores it **row by row (row-major)**:

`address of m[i][j] = base + (i × C + j) × sizeof(type)`

So looping `i` (rows) outside and `j` (columns) inside walks memory in order. That is the natural and fastest way.
