A teacher wants to sort exam papers. She picks one paper, say **score 70**, as the **pivot**. Everyone below 70 goes on the left pile, everyone above on the right pile, and 70 sits in the middle, **already in its final place**. Then she does the same with each pile. Piles of one paper are done.

That is **divide and conquer**: split the problem, solve the parts, and (here) there is nothing to combine.

### Partition (Lomuto)

Use the last item as the pivot. Keep `i` as the end of the "smaller than pivot" zone.

```cpp
int pivot = a[hi], i = lo - 1;
for (int j = lo; j < hi; j++)
    if (a[j] < pivot) swap(a[++i], a[j]);
swap(a[i + 1], a[hi]);   // pivot into place
return i + 1;
```

Then sort `lo .. p − 1` and `p + 1 .. hi`.

### Best vs worst

- **Good pivot** (near the median): each level halves the array, so log n levels of O(n) work gives **O(n log n)**.
- **Bad pivot** (the smallest or largest every time, e.g. sorted input with a last-item pivot): each level removes one item, so n levels gives **O(n²)**.

A random pivot makes the bad case very unlikely.
