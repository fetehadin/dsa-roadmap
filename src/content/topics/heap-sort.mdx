A **sports knockout tournament**. The champion ends up at the top. Remove the champion and the runners-up compete again; the next winner rises to the top. Heap sort keeps finding "the champion" (the maximum) and moving it to the end.

### What is a max-heap?

A **complete binary tree** where every parent is **≥ its children**. So the largest item is always at the **root**.

Because the tree is complete, it fits in an array with no gaps (0-based):

| | index |
| --- | --- |
| left child of i | 2i + 1 |
| right child of i | 2i + 2 |
| parent of i | (i − 1) / 2 |

### heapify (sift down)

If a node is smaller than a child, swap it with the **larger** child and keep going down. O(log n).

### Heap sort in two phases

1. **Build** a max-heap: call heapify on every non-leaf, from `n/2 − 1` down to 0.
2. **Extract** repeatedly: swap `a[0]` (the max) with the last item of the heap, shrink the heap by 1, and heapify the root.

The sorted part grows from the right, just like selection sort, but each "find the max" costs **O(log n)** instead of O(n).

> The same heap is a **priority queue** (`std::priority_queue`), used in Dijkstra's algorithm and schedulers.
