      int firstOccurrence(const int a[], int n, int key) {
          int low = 0, high = n - 1, ans = -1;
          while (low <= high) {
              int mid = low + (high - low) / 2;
              if (a[mid] == key) { ans = mid; high = mid - 1; }
              else if (a[mid] < key) low = mid + 1;
              else high = mid - 1;
          }
          return ans;
      }

Guess-my-number from 1 to 100: you say 50; "higher"; 75; "lower"; 62… Every guess **cuts the possibilities in half**. You'll always win within 7 guesses. That's binary search.

### The algorithm (array must be sorted)

1. `low = 0`, `high = n - 1`.
2. While `low <= high`:
   - `mid = (low + high) / 2`
   - if `a[mid] == key` → found.
   - if `a[mid] < key` → the key can only be on the right: `low = mid + 1`.
   - else → it can only be on the left: `high = mid - 1`.
3. If the loop ends, the key isn't there: return −1.

### Why O(log n)

After each comparison the range halves: n → n/2 → n/4 → … → 1. The number of halvings is **log₂ n**. For a million items that's about **20 comparisons** instead of a million.

### Two requirements

- **Sorted** data, otherwise discarding a half is wrong.
- **Random access** (an array), so jumping to `mid` is O(1). On a linked list, reaching the middle costs O(n), which ruins the speed.
