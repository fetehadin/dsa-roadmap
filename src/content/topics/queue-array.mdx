A **queue** is a line at the bank. New people join at the **rear**. The person at the **front** is served and leaves. Whoever arrived first is served first: **FIFO**, First In, First Out.

| Operation | Meaning |
| --- | --- |
| `enqueue(x)` | add x at the rear |
| `dequeue()` | remove and return the front item |
| `front()` / `peek()` | look at the front item |
| `isEmpty()` / `isFull()` | the usual checks |

### Attempt 1: keep the front at index 0

Enqueue is easy: `q[++rear] = x`. But on dequeue, the front leaves and **everyone shuffles forward**: `q[0] = q[1]; q[1] = q[2]; …`. That is **n − 1 moves per dequeue, so O(n)**. It is like a line where every customer takes a step each time someone is served.

### Attempt 2: move the front instead

Keep a **`front`** index. Dequeue just returns `q[front++]`. No one moves, so it is **O(1)**. It is like the cashier walking down the line instead of the line walking up.

The catch: `front` and `rear` only ever move right. After a few dequeues, the slots before `front` are empty, but `rear` hits `MAX - 1` and the queue says **"full"**. Those slots are wasted forever.

The fix is to let the indices **wrap around** to 0. That is the **circular queue**, next.
