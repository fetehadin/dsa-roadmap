Think of a **kitchen**. You could throw every ingredient into one big box, but then finding the salt takes forever. So you use a spice rack (quick to grab by position), a fridge with shelves (grouped by type) and a stack of plates (you only ever take the top one). Same food, different **organisation**, and each one makes a different job fast.

A **data structure** is exactly that for a program: *a way of storing and organising data in memory so that the operations we need are efficient.*

### How we classify them

- **Primitive**: built into the language, holds one value: `int`, `float`, `char`, `bool`.
- **Non-primitive**: built from primitives, holds a collection.
  - **Linear**: items form a sequence; each has at most one "next": arrays, linked lists, stacks, queues.
  - **Non-linear**: one item can connect to many: trees, graphs.
- **Static vs dynamic** (a separate question): is the size fixed when the program is compiled (array), or can it change while running (linked list, `vector`)?

### Characteristics: what we do with a data structure

Every structure is judged by how well it supports a few standard operations: **traversing** (visit every item), **searching**, **inserting**, **deleting**, **sorting** and **merging**. When we analyse a structure, we ask "how much time and memory does each of these cost?"

### Data structure vs algorithm

A data structure is the *shelf*; an algorithm is the *recipe*. Binary search (an algorithm) only works because the data sits in a sorted array (a data structure). Good programs pick both together.
