You have built stacks and queues yourself, which is what the exam asks for. In real C++ code (and on LeetCode) you use the **Standard Template Library** versions. Same ideas, ready-made.

| | `std::stack<T>` | `std::queue<T>` | `std::deque<T>` |
| --- | --- | --- | --- |
| add | `push(x)` | `push(x)` (at back) | `push_front(x)`, `push_back(x)` |
| remove | `pop()` | `pop()` (from front) | `pop_front()`, `pop_back()` |
| look | `top()` | `front()`, `back()` | `front()`, `back()`, `d[i]` |
| size | `size()`, `empty()` | `size()`, `empty()` | `size()`, `empty()` |

### Trap 1: pop() returns nothing

`s.pop()` removes the top, but **returns `void`**. Read first, then pop:

```cpp
int x = s.top();
s.pop();
```

### Trap 2: empty containers

Calling `top()`, `front()` or `pop()` on an empty container is **undefined behaviour**. It may crash or print garbage. Check `empty()` first.

### What is a deque?

A **d**ouble-**e**nded **que**ue (say "deck"): add or remove at **both** ends in O(1). A stack uses one end; a queue uses both ends, but each for one job. A deque can do both jobs, so it can act as either.
