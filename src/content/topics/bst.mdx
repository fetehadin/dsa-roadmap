Think of a **guessing game**: "I'm thinking of a number. Is it 50?" "Lower." "30?" "Higher." Each answer throws away half the possibilities. That is **binary search** (Chapter 3), but stored as a tree so that **inserting** is also fast.

### The BST property

For **every** node:

- everything in its **left** subtree is **smaller**,
- everything in its **right** subtree is **bigger**.

(Duplicates: this site ignores them. Some courses send them right. Say which rule you use.)

### Search, insert, min, max

All four start at the root and walk **down one path**:

- **search(x)**: equal → found; smaller → go left; bigger → go right; hit `nullptr` → not found.
- **insert(x)**: search for x; where you fall off the tree (`nullptr`), put the new node.
- **min**: keep going **left**. **max**: keep going **right**.

```cpp
Node* insert(Node* root, int x) {
    if (!root) return new Node{x, nullptr, nullptr};
    if (x < root->data) root->left = insert(root->left, x);
    else if (x > root->data) root->right = insert(root->right, x);
    return root;
}
```

### The shape matters

Each step goes down one level, so the cost is the **height h**. A bushy, balanced tree has h ≈ log₂ n (a million items in about 20 steps). But inserting **already-sorted** data makes every node go right. The "tree" becomes a linked list, and search is **O(n)**. (Self-balancing trees fix this, but they are beyond this course.)

### A free sort

**Inorder** traversal (left, node, right) visits a BST in **sorted order**. See the Traversals topic.
