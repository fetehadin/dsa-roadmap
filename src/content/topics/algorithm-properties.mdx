An **algorithm** is a recipe precise enough for a machine: *a finite sequence of well-defined steps that takes some input and produces the correct output.*

A cooking recipe that says "bake until it looks good" is fine for humans, but it isn't an algorithm. A computer can't judge "looks good". Every step must be exact.

### The 11 properties

| Property | Meaning |
|---|---|
| **Finiteness** | It must stop after a finite number of steps. |
| **Definiteness** | Every step is clear and has exactly one meaning. |
| **Sequence** | Steps run in a defined order; each step has a unique next step. |
| **Feasibility** | Every step can actually be carried out with the available resources. |
| **Correctness** | It produces the right output for every valid input. |
| **Language independence** | The steps can be written in any language (C++, Python, pseudocode). |
| **Completeness** | It solves the whole problem, including edge cases. |
| **Effectiveness** | Each step is basic enough to do exactly, in finite time, even by hand. |
| **Efficiency** | It uses as little time and memory as possible. |
| **Generality** | It works for a whole class of problems, not one fixed input. |
| **Input / Output** | Zero or more inputs; at least one output. |

> Memory trick: **"Fine Dogs Sit, Feel Calm, Learn Commands; Every Excited Good I/O."** Silly, but it sticks.

### Algorithm vs program

A **program** is an algorithm written in a specific language and run on a machine. A program may run forever (a web server); an algorithm must finish.
