A **folder on your computer** can hold any number of files and sub-folders. A **company** boss can manage 2 people or 20. These are **general trees** (also called n-ary trees): a node can have **any number** of children.

### The storage problem

A binary tree node has exactly two child pointers. For a general tree, how many should we reserve? Ten? Most would be `nullptr` and wasted, and an eleventh child would not fit.

### The fix: left-child, right-sibling

Give each node just **two** pointers:

```cpp
struct GNode {
    char data;
    GNode* firstChild;    // the leftmost child
    GNode* nextSibling;   // the next brother to the right
};
```

Each parent points only to its **first** child. The children of one parent are chained together like a **linked list** through `nextSibling`.

So "A has children B, C, D" becomes: `A.firstChild = B`, `B.nextSibling = C`, `C.nextSibling = D`.

### It's secretly a binary tree

Rename `firstChild` to `left` and `nextSibling` to `right` and you have a binary tree. That is why this is also called the **binary tree representation of a general tree**. Exams often ask you to draw it: children go **down-left**, siblings go **across to the right**.
