## The task

Build the back-office tool for a small department library. Three data structures, each doing the job it is best at:

| Need | Structure | Why |
| --- | --- | --- |
| The catalogue, kept in id order, with inserts and deletes anywhere | **singly linked list** | no shifting on insert/delete |
| "Undo my last change" | **stack** | the most recent change is undone first (LIFO) |
| Students waiting to borrow | **circular queue** | first come, first served (FIFO), fixed memory |

## Commands (one per line)

| Command | Effect |
| --- | --- |
| `ADD id title…` | add a book (reject duplicate ids); push onto the undo stack |
| `REMOVE id` | remove a book; push onto the undo stack (keep the title!) |
| `UNDO` | reverse the last ADD or REMOVE |
| `REQUEST name id` | enqueue a borrow request (only for books that exist) |
| `SERVE` | dequeue the oldest request: lend the book, or re-queue the request if it is out |
| `RETURN id` | mark a book as returned |
| `LIST` | print the catalogue in id order |

## Rules

- Write your own list, stack and queue. No `std::list`, `std::stack` or `std::queue`.
- Every `new` has a matching `delete`. Check with `g++ -std=c++17 -fsanitize=address`.
- Never crash on bad input: unknown ids, empty undo, empty queue, full queue.
